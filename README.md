# LinkDock

一个面向浏览器扩展场景设计的轻量级书签管理系统。

LinkDock 的目标不是做一个“大而全”的导航站，而是把“保存、整理、找回、再次打开”这条书签使用链路做得足够轻、足够快、足够顺手。它同时提供 Web 端书签主页和 Chrome 扩展侧边栏工作台，适合个人长期使用，也适合作为一个完整的前后端一体化项目进行学习、二次开发和工程能力展示。

## 项目定位

浏览器自带收藏夹的问题通常不在“能不能保存”，而在保存之后很难整理、很难找回、很难形成持续使用习惯。LinkDock 尝试围绕这些痛点做一个小而美的解决方案：

- 快速保存当前页面，尽量减少用户操作成本。
- 通过分类、标签、状态、常用、最近访问等维度提高找回效率。
- 在扩展侧边栏中完成日常书签管理，不强迫用户频繁切换页面。
- 默认提供公共热门书签，未登录用户也能直接体验核心浏览能力。
- 登录后拥有独立数据空间，支持自定义分类、书签排序、拖拽移动和密码找回。

## 核心功能

### 书签管理

- 新增、编辑、删除书签。
- 新增、编辑、删除分类。
- 分类支持常用图标选择，也支持手动输入自定义 emoji。
- 书签按分类展示，支持所有书签总览。
- 新增书签默认追加到当前分类最后。
- 支持拖拽排序。
- 支持跨分类拖拽移动。
- 支持将书签拖拽到侧边分类目录上，像在 macOS 文件夹中移动文件一样完成归类。
- 支持空分类作为拖拽目标，避免“空分类无法放入第一个书签”的体验断点。

### 快速保存

- Chrome 扩展侧边栏内显示当前页面信息。
- 当前页面未收藏时展示快捷保存入口。
- 当前页面已收藏时自动隐藏快捷保存模块，减少界面噪音。
- 右键菜单支持保存当前页、保存链接、保存选中文本。
- 快捷键支持快速唤起保存流程。
- 保存时自动获取网页标题、描述和站点图标。
- 保存时自动落入推荐分类、最近使用分类或当前分类。
- 已收藏网址会被识别并阻止重复添加。

### 查找与筛选

- 支持按书签名称搜索。
- 支持按 URL 和域名搜索。
- 支持按描述搜索。
- 支持按标签搜索。
- 支持 `domain:xxx` 形式的域名过滤。
- 支持 `tag:xxx` 形式的标签过滤。
- 支持最近新增、最近访问、常用、稍后读、未整理等快捷筛选。
- 支持访问次数统计和最近访问时间记录。

### 轻量状态系统

- 常用：适合标记高频打开的核心站点。
- 稍后读：适合临时保存但需要后续处理的页面。
- 未整理：适合刚保存、还没有认真归类的内容。
- 无状态：适合已经整理完成、不需要额外提醒的普通书签。

### 智能辅助

- URL 规范化，减少同一网址因为写法不同造成的重复。
- 保存前检测完全重复网址。
- 保存时检测同域名书签。
- 根据同域名已有书签推荐分类。
- 记住最近使用分类，提高连续保存效率。

### 账号系统

- 用户注册、登录、退出。
- 用户名唯一性校验。
- 用户名支持 3-20 位字母、数字或下划线。
- 密码强度校验，要求至少 8 位且包含字母和数字。
- 密码使用 bcrypt 哈希存储。
- 支持安全问题找回密码。
- 支持登录后修改密码。
- 新用户注册后自动初始化默认分类和热门书签。
- 支持超级管理员账号维护系统默认分类和默认书签。

### 超级管理员

- 内置超级管理员入口，适合个人项目低成本维护默认数据。
- 支持通过 `/admin/seed` 独立页面维护默认分类和默认书签。
- 默认分类支持图标选择和自定义 emoji 输入。
- 默认书签支持自动获取标题、描述和图标。
- 管理页面只对超级管理员开放，后端接口也会做权限校验兜底。

### 未登录体验

- 未登录用户可以浏览默认公共书签。
- 未登录用户点击新增、编辑、拖拽整理、快捷保存等写操作时，引导登录。
- 未登录状态不会把公共默认书签误判为用户自己的收藏。

### 浏览器扩展

- 支持 Chrome Manifest V3。
- 支持浏览器侧边栏工作台。
- 支持新标签页替换为 LinkDock 书签主页。
- 支持右键菜单快速保存。
- 支持快捷键快速保存当前页。
- 扩展配置集中在 `extension/config.js`，方便在本地和线上地址之间切换。

## 架构设计

LinkDock 采用前后端分离开发、生产环境静态资源内嵌后端服务的模式。

开发环境下：

- 前端由 Vite 启动在 `http://localhost:3000`。
- 后端由 Beego 启动在 `http://localhost:8080`。
- Vite 通过 dev server proxy 将 `/api` 请求转发到后端。
- Chrome 扩展通过 iframe 加载前端页面，并附带当前标签页信息。
- Web 端使用 Vue Router 管理页面路由，用户书签主页为 `/`，超级管理员默认数据管理页为 `/admin/seed`。

生产构建后：

- 前端构建产物输出到 `backend/static`。
- 后端可以直接托管前端静态页面。
- API 与页面可以由同一个后端服务提供。

这种方式兼顾了开发体验和个人项目部署成本，适合资源有限的独立开发者维护。

## 路由设计

| 路径 | 页面 | 权限 |
| --- | --- | --- |
| `/` | 用户书签主页 | 未登录可浏览默认公共书签，登录后管理个人书签 |
| `/admin/seed` | 默认书签管理页 | 仅超级管理员可访问 |

前端路由负责页面切换和体验控制，后端接口负责真正的权限兜底。即使用户手动访问 `/admin/seed`，没有超级管理员权限也无法读取或保存默认数据。

## 数据模型

核心数据模型包括：

- `User`：用户信息、密码哈希、安全问题和安全答案。
- `Category`：用户自己的书签分类，包含排序字段。
- `Site`：书签主体，包含 URL、描述、图标、标签、收藏状态、工作流状态、访问次数、最近访问时间和排序字段。

书签和分类都绑定 `user_id`，保证不同用户之间的数据隔离。

## API 概览

### 认证相关

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/auth/register` | 注册 |
| `POST` | `/api/auth/login` | 登录 |
| `POST` | `/api/auth/logout` | 退出 |
| `GET` | `/api/auth/me` | 获取当前登录状态 |
| `POST` | `/api/auth/check-username` | 检查用户名是否可用 |
| `POST` | `/api/auth/recovery-question` | 获取找回密码安全问题 |
| `POST` | `/api/auth/reset-password` | 通过安全问题重置密码 |
| `POST` | `/api/auth/change-password` | 登录后修改密码 |

### 数据相关

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/public/data` | 获取未登录默认公共数据 |
| `GET` | `/api/user/data` | 获取当前用户分类和书签 |
| `POST` | `/api/categories` | 创建分类 |
| `PUT` | `/api/categories/:id` | 更新分类 |
| `DELETE` | `/api/categories/:id` | 删除分类 |
| `POST` | `/api/categories/reorder` | 更新分类排序 |
| `POST` | `/api/sites` | 创建书签 |
| `PUT` | `/api/sites/:id` | 更新书签 |
| `DELETE` | `/api/sites/:id` | 删除书签 |
| `POST` | `/api/sites/reorder` | 更新书签排序和分类 |
| `POST` | `/api/sites/:id/visit` | 记录访问次数和最近访问时间 |
| `POST` | `/api/sites/:id/state` | 更新常用状态或工作流状态 |
| `POST` | `/api/sites/fetch-metadata` | 获取网页标题、描述和图标 |

## 本地运行

### 环境要求

- Node.js 18 或更高版本
- npm
- Go
- Chrome 或 Edge 浏览器

### 安装依赖

```bash
npm install
```

如果只开发前端，也可以进入 `frontend` 单独安装：

```bash
cd frontend
npm install
```

### 准备本地配置

项目不会提交真实的本地配置文件。首次运行前，请复制示例配置：

```bash
cp backend/conf/app.example.conf backend/conf/app.conf
```

默认示例配置会使用 SQLite，本地数据库文件会生成在 `backend/linkdock.db`。

### 启动开发环境

在项目根目录执行：

```bash
npm run dev
```

启动后访问：

```text
http://localhost:3000
```

默认情况下：

- 前端端口：`3000`
- 后端端口：`8080`
- 默认数据库：`backend/linkdock.db`

### 构建生产产物

```bash
npm run build
```

构建产物会输出到：

```text
backend/static
```

### 类型检查

```bash
npm run lint
```

### 后端编译检查

```bash
cd backend
go build ./...
```

## 数据库配置

项目默认使用 SQLite，适合本地开发和个人部署。

真实本地配置位于：

```text
backend/conf/app.conf
```

开源仓库只提交示例配置：

```text
backend/conf/app.example.conf
```

可以通过环境变量覆盖数据库配置：

```bash
DB_DRIVER=sqlite
DB_PATH=linkdock.db
```

如果需要使用 MySQL，可以设置：

```bash
DB_DRIVER=mysql
DB_USER=root
DB_PASS=your_password
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=linkdock
```

## 初始化数据

默认公共书签和新用户初始化书签来自：

```text
backend/conf/seed.json
```

你可以在这里维护适合自己产品定位的默认分类和默认热门书签。

也可以使用超级管理员账号在浏览器页面中维护默认数据：

1. 启动项目后访问 `http://localhost:3000`。
2. 使用 `admin / 123456` 登录。
3. 第一次登录时，如果数据库中还没有管理员用户，系统会自动创建超级管理员。
4. 登录后点击右上角账户菜单。
5. 进入“默认书签管理”页面，也可以直接访问 `/admin/seed`。
6. 在独立管理页面中新增、编辑、删除默认分类和默认书签。
7. 为默认分类选择常用图标，或手动输入自定义 emoji。
8. 为默认书签自动获取网页标题、描述和图标，也可以手动调整。
9. 点击“保存默认数据”后，系统会写回 `backend/conf/seed.json`。

默认数据保存后会影响两类场景：

- 未登录用户看到的公共默认书签。
- 新用户注册后自动初始化到个人账户中的默认书签。

## 浏览器扩展安装

LinkDock 的扩展能力主要依赖 Chrome 侧边栏和新标签页。

### 安装步骤

1. 打开 Chrome 或 Edge。
2. 进入扩展管理页面：`chrome://extensions/`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择项目中的 `extension` 文件夹。
6. 确保主应用已经启动：`npm run dev`。
7. 点击扩展图标，打开 LinkDock 侧边栏。

### 修改扩展指向地址

扩展默认指向：

```text
http://localhost:3000/
```

如果部署到线上，只需要修改：

```text
extension/config.js
```

示例：

```js
window.LinkDockConfig = {
  baseUrl: 'https://your-domain.com/',
};
```

## 工程亮点

### 1. 围绕真实使用链路设计，而不是堆功能

项目围绕“保存一个网址”和“找回一个网址”两个核心场景迭代。侧边栏工作台、右键保存、快捷键保存、重复检测、最近分类、状态筛选等功能都服务于同一条用户路径，避免功能分散。

### 2. Web 应用与浏览器扩展协同

扩展没有重复实现一套复杂 UI，而是通过侧边栏 iframe 复用 Web 应用能力。扩展层负责感知浏览器上下文，Web 层负责数据展示和交互逻辑，职责边界清晰。

### 3. 拖拽排序与跨分类移动

书签支持同分类排序、跨分类移动，也支持拖到侧边栏分类目录完成移动。前端维护拖拽中的临时状态，后端统一通过批量排序接口持久化，保证交互体验和数据一致性。

### 4. 未登录体验和登录后体验分层

未登录用户可以浏览默认公共数据，降低体验门槛；涉及写入的行为会引导登录。登录后使用独立用户数据，并在注册后自动初始化默认内容。

### 5. 去重与智能归类

后端进行 URL 规范化和重复检测，前端在保存时提示同域名书签与推荐分类，减少重复收藏和整理负担。

### 6. 低成本部署取舍

项目默认使用 SQLite，生产构建后由 Go 后端直接托管前端静态资源，不强依赖复杂云服务。对个人开发者来说，维护成本更低，也更符合小型产品从 0 到 1 的现实约束。

### 7. 渐进式账号系统

在不依赖第三方登录和付费邮件服务的前提下，先实现了自定义账号、安全问题找回密码、修改密码和密码哈希存储，为后续接入邮箱验证码、OAuth 或更完整的会话系统留下扩展空间。

## 安全说明

当前项目适合个人使用、本地部署、作品展示和继续迭代。若用于正式公网生产环境，建议进一步完善：

- 使用 JWT、Session 或更完整的 Token 签发与过期机制。
- 强制 HTTPS。
- 对敏感接口增加限流和风控。
- 将数据库密码等敏感配置迁移到环境变量或密钥管理服务。
- 为找回密码流程接入邮箱验证码或其他更强身份验证方式。
- 增加 CSRF、CORS、日志审计等生产级安全配置。

## 开源前建议

如果你准备将本项目发布到 GitHub，建议在提交前确认：

- 不提交真实本地配置文件，例如 `backend/conf/app.conf`。
- 不提交本地数据库文件，例如 `backend/linkdock.db`。
- 不提交编译生成的后端二进制文件。
- 不提交包含真实密码、域名、密钥的配置。
- 提交安全的示例配置文件，例如 `backend/conf/app.example.conf`。
- 保留 `backend/conf/seed.json` 作为默认演示数据。
- 将前端底部 Footer 中的 `OPEN_SOURCE_URL` 替换为真实 GitHub 仓库地址。
- 如果需要展示线上效果，可以在 README 顶部补充演示地址和截图。

如果这些文件之前已经被 Git 跟踪过，只加入 `.gitignore` 还不够，需要把它们从 Git 索引中移除，但保留本地文件：

```bash
git rm --cached backend/conf/app.conf backend/linkdock.db backend/linkdock.db backend/backend
```
